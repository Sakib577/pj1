Expense Tracker Flutter App - AI Handoff
========================================

Purpose
-------
This is a Flutter expense tracker for Android and Web. It has a polished UI shell,
email/password authentication, email verification, Firestore access control,
per-user categories synced to Firestore, and transactions / planned payments /
debts / shopping-list items persisted to Firestore with live snapshot sync. Local
Android notifications remind about upcoming planned payments two days before, one
day before, and on the due day. Budgets and savings goals are persisted to
Firestore and support editing. On top of tracking, the app has a full Analytics
module (Statistics page with adaptive line/donut/gauge charts) and a Reports
module that computes formal accounting statements and exports them to vector PDF
or CSV, shared from the device.

Recent implementation notes (August 2026)
-----------------------------------------
- Budgets support create, edit, delete, repeating periods, and Firestore persistence.
- Analytics module (lib/analytics/): a self-contained Statistics page reached from
  the dashboard drawer. All computation lives in the pure analytics_service.dart;
  chart widgets are thin wrappers around fl_chart (wrapped so the library can be
  swapped). Data is read ONLY from the already-synced in-memory FinanceAppState
  (never Firestore directly, never mock data). No new state-management package:
  StatisticsController (ChangeNotifier) + the existing FinanceAppScope pattern.
- The Trends card (lib/analytics/widgets/trends_card.dart) is a dropdown-driven
  line chart covering spending, income vs expense, cash flow, savings trend, and
  balance history. Income-vs-expense and spending trends render as LINE charts
  (not bars) so short windows show real curves instead of isolated dots.
  Bucket granularity is adaptive to the window length (<=45d daily, <=180d
  weekly, else monthly) mirroring calculateSavingsTrend, so a single-month window
  never collapses to two dots.
- The cash-flow net line is painted LAST (drawn on top of income/expense) in pure
  black (0xFF000000) with a slightly wider stroke, for instant readability.
- calculateSavingsTrend sums contributions (negative transactions whose category
  is a savings goal) so "Savings Trend" reflects money actually moved into goals.
- calculateCashFlowForecast is continuous: the actuals look-back ends at the last
  transaction date and the forecast starts on the following day (no gap).
- formatCurrencyNoCents converts then rounds, fixing an off-by-display bug where
  large converted amounts (e.g. 500 BDT) could render with trailing digits.
- Savings transactions carry idPrefix 'savings-{goal.id}' and deleteTransaction
  reverts the goal balance when such a linked transaction is deleted.
- Reports module (lib/reports/): read-only accounting engine (report_service.dart)
  classifying every transaction into operating/investing/financing for a formal
  Cash Flow Statement, plus Income Statement (P&L), Balance Sheet (cash + savings
  + money lent vs money borrowed = net worth), Budget vs Actual, Debt Report, and
  Savings & Net Worth. Reports page has a preset/custom period picker.
- PDF export (lib/utils/pdf_export.dart) renders VECTOR charts (custom CustomPaint
  via pw.PdfGraphics). The trend chart is sized by pw.LayoutBuilder to the actual
  card content width (fallback _pageWidth) so PDF graphs never overflow into
  adjacent text; flat series (minV==maxV) expand to avoid invisible plots. CSV
  export (lib/utils/csv_export.dart) is RFC 4180 with amounts converted to the
  user's display currency. Exports are shared via share_plus; paths come from
  path_provider. Verified locally by rendering PDF->PNG (pdftoppm) + PIL pixel
  analysis; temp render tests are deleted after use.
- GroupedBar gained an optional date field (bucket start) populated by
  calculateIncomeExpenseComparison so income/expense can render as time-series.
- fl_chart tooltip builder now passes spot.barIndex instead of a hardcoded 0.
- Statistics page cards: Trends (dropdown), Cash Flow Summary, Category Donut,
  Spending Pattern, Top Expenses, Debt-to-Income gauge, Monthly Overview, Income
  Analytics, Budget Progress, Cash Flow Forecast, Next-Month Estimate.
- Savings is the renamed Savings Goals page. Goals support create, edit, delete,
  add funds, withdraw funds, Firestore persistence, and Active/Completed sections.
  Withdrawals are bounded by the current balance and recorded as reversal/income
  transactions; a completed goal returns to Active when withdrawn below target.
- Planned-payment editing includes the start-date picker. Reminders are scheduled
  locally at 9 AM for two days before, one day before, and the due day.
- The Notifications page shows the latest 10 reminder messages using the same
  titles and bodies as local phone notifications, without "Planned payment added".
- Dialog text controllers remain alive through closing animations before disposal.
  This applies to savings, budgets, transactions, planned payments, and category
  dialogs, preventing disposed-controller and cascading framework errors.
- Category cards clip rounded press feedback and remove ExpansionTile divider
  artifacts. Other Income uses a gift-card icon instead of the generic category icon.
- Transaction history starts with the newest 100 records and reveals older records
  in 100-item batches. It supports text search, category filtering, and date-range
  filtering. Firestore's live transaction listener is limited to the newest 100;
  the full history is hydrated separately to preserve accurate totals and budgets.

----------

- Firebase Core, Firebase Authentication, Cloud Firestore
- HTTP client with ExchangeRate-API's open endpoint for daily USD-based FX rates
- Firebase project ID: expense-tracker-sakib

- Supported Firebase platforms: Android and Web

Important files
---------------
- lib/main.dart: initializes Firebase, sets the theme, starts MyApp. After
  initialization it enables Firestore offline persistence globally
  (Settings(persistenceEnabled: true, cacheSizeBytes: CACHE_SIZE_UNLIMITED)) so
  reads come from a durable on-device cache and offline writes are buffered and
  replayed when connectivity returns (Android/iOS and Chrome; best-effort on
  browsers that lack IndexedDB support).
- lib/auth_gate.dart: routes signed-out users to AuthPage, unverified users to
  EmailVerificationPage, and verified users to DashboardPage.
- lib/pages/auth_page.dart: email/password sign-up and sign-in.
- lib/pages/email_verification_page.dart: resend verification email and refresh
  verification state.
- lib/pages/dashboard_page.dart: home screen with bottom navigation (Home, Budgets,
  Savings, Profile) and the side drawer that opens the tools. On first load it
  syncs user data (categories + persisted records) and then checks planned payments
  that are due today or overdue, showing a "Payments due" dialog with Confirm &
  record / Skip.
- lib/pages/add_transaction_page.dart: transaction form with an Income/Expense
  segment, recent category shortcuts, an optional note, a calculator keypad that
  supports + - * / and = expressions, and a save button. It calls the in-memory
  addTransaction.
- lib/pages/categories_page.dart: expense/income category manager, subcategories,
  and user-defined emoji categories. Also used in selection mode from Add
  Transaction.
- lib/pages/category_detail_page.dart: reusable parent-category/subcategory selector
  used by Add Transaction.
- lib/pages/budget_page.dart: Budgets tab UI with create/edit/delete actions,
  repeating periods, per-category cards, and Firestore persistence.
- lib/pages/savings_page.dart: Savings tab UI with create/edit/delete, add/withdraw
  funds, Active/Completed sections, and Firestore persistence.
- lib/pages/transactions_page.dart: "Recent Transactions" page with All / Income /
  Expenses filter segments and the same tile theme as the dashboard list. Tapping a
  tile opens an action sheet with Edit (amount, income/expense, note) and Delete
  (with confirmation). Reachable from the dashboard "View All" link.
- lib/pages/planned_payments_page.dart: planned payments list plus the "New Planned
  Payment" form. Payments pick an income/expense category (with subcategory), a
  title, an amount, a repeat schedule (one time / daily / weekly / monthly / custom
  every N days), and a start date. Stored in memory via FinanceAppState. Reachable
  from the dashboard "View All" link and the drawer.
- lib/pages/finance_tools_page.dart: currency converter and report tools only.
  Planned payments, debts, and the shopping list moved to their own dedicated pages.
- lib/pages/debts_page.dart: debts list with an Active / Closed toggle, each split
  into Borrowed and Lent sections, plus the "New Debt" form (person, amount,
  borrowed/lent, note). Active debts show a "Repaid" button next to the close
  action; the close button is named "Forgive" for lent debts and "Close" for
  borrowed ones. Repaid/closed debts show a status label (Repaid / Closed /
  Forgiven) and a Reopen button. Stored in memory via FinanceAppState. Reachable
  from the drawer.
- lib/pages/shopping_list_page.dart: shopping list grouped by the Shopping category
  subcategories (with a General group). The "Add Item" flow is chip-based: the Add
  form shows subcategory chips (General + each subcategory) plus an "Add
  subcategory" chip; tapping a subcategory opens an item-name dialog and adds the
  item (General items use no subcategory). Checking an item prompts for its price
  and records it as a Shopping expense transaction. Items persist to Firestore and
  sync via a live snapshot stream.
- lib/pages/profile_page.dart: profile card, balance/income/expenses stats, and sign
  out. Also hosts the Select Currency entry point to SettingsPage.
- lib/pages/settings_page.dart: select the default display currency (searchable
  bottom-sheet picker) and refresh live rates.
- lib/state/finance_app_state.dart: global financial state (transactions, debts,
  shopping items, budgets, savings goals, categories cache, currency). Loads and
  watches categories from Firestore for the signed-in user and subscribes to live
  snapshot streams for transactions, planned payments, debts, and shopping items,
  recomputing balance, income, and expenses from those records on every change.
  Every mutation is written through to Firestore (failures are swallowed so offline
  use never blocks the UI; Firestore's own on-device queue replays offline writes
  when connectivity returns). completeShoppingItem adds a Shopping expense
  transaction when an item is checked off. Debts affect the balance: borrowing adds
  money and lending subtracts it at creation; Repaid reverses that money movement;
  Close/Forgive never moves money. confirmPlannedPayment records a due payment as a
  real transaction and removes it from the planned list (so a confirmed amount
  shows only as a transaction, never as an upcoming payment). On load, expense
  categories are normalized so the "Missing/
  Uncategorized" catch-all becomes "Missing" and is kept first in the list.
  Subcategories carry a per-name emoji (subcategoryEmojis) chosen via an emoji
  picker for user-defined ones or derived from a curated default map. The state
  tracks SyncStatus (synced / offline / pending) from the transactions snapshot
  metadata and exposes syncStatus, isOffline, and hasPendingSync.
- lib/state/finance_app_state.dart (FinanceAppScope): FinanceAppScope is a regular
  InheritedWidget carrying FinanceAppState. MyApp listens to the state and updates
  a revision number on the scope, avoiding the fragile InheritedNotifier/dialog
  lifecycle path that caused Flutter '_dependents.isEmpty' assertions. Dialog
  controller disposal is delayed until route transitions finish.
- lib/services/category_repository.dart: reads/writes/seeds categories in Firestore
  at users/{uid}/expense_categories and users/{uid}/income_categories and exposes a
  live snapshot stream.
- lib/services/finance_repository.dart: reads/writes transactions, planned
  payments, debts, and shopping items in Firestore at users/{uid}/transactions,
  users/{uid}/planned_payments, users/{uid}/debts, and users/{uid}/shopping_items.
  Exposes both one-time loads and live snapshot streams for every collection, plus
  watchSyncStatus() reporting SyncStatus derived from the transactions snapshot's
  metadata (includeMetadataChanges: true).
- lib/services/payment_reminder_service.dart: wraps flutter_local_notifications +
  flutter_timezone + timezone to schedule Android reminders at 9 AM local time two
  days before, one day before, and on each planned payment's due date. Reschedules
  (cancel-all + re-add) on every app open or payment change.
- lib/services/exchange_rate_service.dart: fetches USD exchange rates from
  ExchangeRate-API.
- lib/models/finance_models.dart: UI-facing model classes. They contain Flutter
  IconData and Color, so they should not be used directly as Firestore database
  models, but they do carry toMap/fromMap serialization (icons via a stable name
  mapping, colors via ARGB ints) used by the finance repository. ExpenseCategory has
  a toMap/fromMap for the Firestore category docs, a subcategoryEmojis map, a
  subcategoryEmoji() lookup, a defaultSubcategoryEmoji() fallback, and a curated
  subcategoryIcon() map of Material icons for built-in subcategories. SyncStatus is an enum
  (synced / offline / pending) used to surface offline/syncing state. PlannedPayment carries a repeat
  schedule (RepeatFrequency once/daily/weekly/monthly/custom), a nextDue() helper,
  a lastConfirmedDate used to skip already-confirmed occurrences, and a
  needsConfirmation flag. DebtItem uses a DebtSettlement enum (active/closed/repaid)
  so repaid vs forgiven/closed records stay distinct, and ShoppingItem (subcategory,
  done flag, price) are simple in-memory models.
- lib/analytics/: Statistics module (engine + widgets). Key entry points:
  lib/pages/statistics_page.dart (screen), lib/analytics/services/analytics_service.dart
  (pure computation engine), lib/analytics/providers/statistics_controller.dart
  (ChangeNotifier for the active DateRange + cached StatisticsBundle),
  lib/analytics/charts/ (fl_chart wrappers: stat_line_chart, stat_bar_chart,
  stat_donut_chart, stat_circular_gauge, chart_tooltip, chart_theme),
  lib/analytics/widgets/ (stat cards incl. trends_card.dart with the dropdown
  line chart and adaptive granularity), lib/analytics/models/
  (DTOs incl. GroupedBar.date), lib/analytics/utils/date_ranges.dart
  (presets + windowing).
- lib/reports/: Reports module. lib/reports/reports_page.dart (list + detail UI
  with preset/custom period picker), lib/reports/services/report_service.dart
  (pure accounting engine for Cash Flow / Income Statement / Balance Sheet /
  Budget vs Actual / Debt / Savings & Net Worth), lib/reports/models/report_models.dart
  (ReportKind enum + DTOs), lib/reports/widgets/ (report_line_list,
  statement_section_card).
- lib/utils/pdf_export.dart: vector PDF report export. Trend/forecast charts are
  custom-painted via pw.PdfGraphics and sized with pw.LayoutBuilder to the card
  content width (fallback _pageWidth) so they never overflow into text; flat
  series expand to stay visible. Uses path_provider + share_plus.
- lib/utils/csv_export.dart: RFC 4180 CSV of all transactions (oldest first),
  amounts converted to the display currency.
- lib/utils/currency_settings.dart: current display currency and loaded rates.
  The selected code is kept even when the loaded rates map does not yet contain it
  (it defaults to rate 1 until live FX rates arrive). This is what makes the
  user's currency survive sign-out / sign-in: on login the stored code is loaded
  from Firestore before the rates, and without this behavior the code was reset to
  USD because the initial rates map only contained USD.
- lib/utils/currency_formatters.dart: formatCurrency / formatCurrencyNoCents /
  formatCurrencyInput helpers (display currency with manual thousands grouping).
  formatCurrency omits decimals entirely when the fraction is zero and trims
  trailing zeros otherwise (1000.00 -> "1000", 12.50 -> "12.5"), so dashboards
  never show noisy ".00".
- lib/widgets/: shared UI building blocks (TransactionTile, EmptyStateCard,
  PlannedPaymentCard, CategoryLogo, SubcategoryLogo) reused by the dashboard and
  the transactions / planned payments / categories pages. EmptyStateCard renders
  content-sized and top-left aligned: it wraps its card in Align(topLeft) +
  UnconstrainedBox(constrainedAxis: Axis.horizontal) so the inner Row never
  stretches vertically (Flex fills a bounded cross axis). CategoryLogo renders the
  orange Material icon for built-in categories or the emoji for user-defined ones;
  SubcategoryLogo does the same per subcategory (curated icon for built-ins,
  emoji for user-defined).
- lib/data/: currently an empty directory, reserved for future repository/database
  code.
- firestore.rules: deployed Firestore rules.
- firebase.json: Firebase CLI configuration and the Firestore rules reference.
- lib/firebase_options.dart: generated Firebase configuration. Do not edit manually.
- test/widget_test.dart: single widget test. Currently OUTDATED and failing; it
  references keys (transaction-title, key-2, key-5, key-., key-0) that no longer
  exist on the calculator-keypad Add Transaction page.

Authentication and security
---------------------------
- Email/Password Authentication is enabled in Firebase Console.
- On account creation, the app sends a verification email.
- Users cannot open the dashboard until they verify their email and tap "I verified
  my email".
- Firestore rules are deployed. They allow only verified users to access their own
  path: users/{uid}/... . All other Firestore paths are denied.
- If rules change, deploy them with:
  firebase deploy --only firestore:rules --project expense-tracker-sakib

Current behavior
----------------
- A verified user can sign in, view the dashboard, add a transaction, and
  sign out.
- The dashboard has four bottom tabs (Home, Budgets, Savings, Profile) plus a
  side drawer with Dashboard, Categories, Statistics, Reports, Planned Payments,
  Debts, Shopping List, Budgets, Savings, Profile & Settings, Currency Converter,
  and Export Report.
  The "View All" links on Recent Transactions and Planned Payments open dedicated
  pages. Several buttons (notifications, more options) only show placeholder
  snackbars.
- The Recent Transactions page lists all transactions with All / Income / Expenses
  filter segments; the dashboard shows the five most recent.
- Planned payments have a dedicated list page and creation form. Each payment is
  based on an income/expense category (with an optional subcategory), has an amount,
  and repeats one time, daily, weekly, monthly, or custom (every N days) starting
  from a chosen date. Cards show the repeat badge and the next due date (overdue /
  due today). Payments can be deleted. On app open the dashboard checks for payments
  due today or overdue and shows a "Payments due" dialog with three actions: Skip,
  Delete (removes the scheduled payment), or Confirm & record (turns each into a
  real transaction and removes it from the planned list, so a confirmed amount shows
  only as a transaction).
- Debts have a dedicated page with an Active / Closed toggle; each view is split into
  Borrowed and Lent sections. A debt stores a person, an amount, a type
  (borrowed/lent), and an optional note. Adding a debt moves the balance (borrowed
  adds money, lent takes it out); the Repaid action reverses that money movement,
  while Close/Forgive settles the record without touching the balance. Repaid,
  closed, and forgiven debts show in the Closed tab with a status label and a Reopen
  button. Debts persist to Firestore.
- The Shopping List page groups items by the Shopping category's subcategories (with
  a General group). The Add Item flow is chip-based: the Add form shows subcategory
  chips plus an "Add subcategory" chip; tapping a subcategory opens an item-name
  dialog and adds the item (General items get no subcategory). Subcategories persist
  to Firestore via the existing category sync. Checking off an item prompts for its
  price and automatically adds a Shopping expense transaction. Items persist to
  Firestore and sync live.
- Categories ARE now persisted per user. On first dashboard load the app seeds the
  default categories into Firestore (users/{uid}/expense_categories and
  income_categories), loads them, and subscribes to live snapshots. User-defined
  emoji categories, subcategories, and deletions sync to Firestore. The add/delete
  flows are triggered from finance_app_state.dart.
- The Categories page has Expense and Income tabs matching the Add Transaction type
  selector. Both kinds have built-in parent categories and useful subcategories.
  The expense catch-all is "Missing" (a legacy "Missing/Uncategorized" name is
  normalized to "Missing" on load and kept first in the list); deleted categories
  move their transactions to it.
  Income includes salary/wages, dues received, interest, dividends, loan
  repayments, rental income, sales, gifts, refunds, freelance/side work, and other
  income.
- Built-in categories use orange Material icons; emojis are reserved for
  user-defined categories. Built-in SUBcategories also use curated orange Material
  icons (subcategoryIcon map in finance_models.dart); only user-defined
  subcategories show emojis. The Add Transaction page shows horizontal category
  shortcuts (recently used tracked separately for income and expenses, plus a "Add
  category" shortcut). Tapping a category opens the reusable category/subcategory
  selector (CategoryDetailPage), whose header always shows the tapped category's
  own logo (its Material icon, not a generic file/folder icon). A category is
  required by default; the text field is an optional note. Transactions currently
  record the selected category/subcategory name for later analytics.
- User-defined categories and user-added subcategories can be deleted. Their
  affected in-memory transactions are reassigned to Other.
- Currency settings loads the provider's supported ISO currencies at runtime. All
  amount formatting uses the selected display currency. Financial totals are held
  internally in USD and newly entered amounts are converted to USD using the
  currently loaded rate. The chosen currency is persisted to Firestore at
  users/{uid}/settings/currency on selection and loaded again on every sign-in, so
  the previously selected currency is restored instead of resetting to USD. Amount
  strings never show trailing ".00": formatCurrency hides zero decimals and trims
  trailing zeros (1000.00 -> "1000", 12.50 -> "12.5"). The dashboard's Total
  Balance and Income/Expense stat cards keep equal heights: the stat cards share a
  single font size computed from the longest amount (so a huge Income shrinks BOTH
  cards), the balance font shrinks for very large totals, and both are wrapped in
  FittedBox(scaleDown) so numbers never overflow.
- FinanceAppScope is a regular InheritedWidget updated by MyApp's state listener;
  screens reading app state rebuild on state changes without the former
  InheritedNotifier dialog-lifecycle problem. Live Firestore updates, new
  transactions, the offline/syncing banner, and currency changes appear immediately.
- Transactions, planned payments, debts, and shopping-list items are persisted to
  Firestore under users/{uid}/transactions, users/{uid}/planned_payments,
  users/{uid}/debts, and users/{uid}/shopping_items. The state subscribes to live
  snapshot streams for all four, so edits made on one device appear on others and
  balance/income/expenses stay in sync. Firestore offline persistence is enabled
  globally (main.dart), so on Android/iOS and Chrome reads come from a durable
  on-device cache and offline edits are buffered and replayed on reconnect. The
  dashboard shows a slim banner when the data is offline ("Offline — changes saved
  locally") or has pending local writes ("Syncing…"), driven by SyncStatus surfaced
  from the transactions snapshot metadata. Transactions
  can be edited (amount / income-expense / note) or deleted from the Recent
  Transactions page. Budgets and savings goals are persisted and editable.
- Android local notifications remind about planned payments with "Payment coming up
  in 2 days", "Payment coming up in 1 day", and "Payment due today" notifications,
  all at 9 AM device-local time. Reminders are (re)scheduled on every app
  open and whenever payments change. Android core library desugaring is enabled in
  android/app/build.gradle.kts (required by flutter_local_notifications), the
  manifest declares RECEIVE_BOOT_COMPLETED plus the plugin's scheduled-notification
  receivers, and a white notification_icon drawable is provided. The
  POST_NOTIFICATIONS runtime prompt is requested on Android 13+ via
  PaymentReminderService.
- Budgets and Savings tabs create, edit, delete, and persist their records. Savings
  also supports adding/withdrawing funds and Active/Completed goal sections.
- The Statistics page (drawer) shows a scrollable set of analytics cards over a
  user-chosen date range (today / last 7 / last 30 / this month / last month /
  custom). The Trends card is a dropdown-driven line chart (spending, income vs
  expense, cash flow with black net line drawn on top, savings trend, balance
  history) whose bucket granularity adapts to the window length so short windows
  show full curves, not isolated dots. Other cards cover category donut, spending
  pattern, top expenses, debt-to-income, monthly overview, income analytics,
  budget progress, cash-flow forecast, and next-month estimate.
- The Reports page (drawer) lists six formal statements computed by
  report_service.dart from the in-memory transactions/debts/goals/budgets:
  Cash Flow Statement (operating/investing/financing + beginning/ending cash),
  Income Statement (P&L with gross margin), Balance Sheet (net worth), Budget vs
  Actual, Debt Report, and Savings & Net Worth. Each can be exported as a vector
  PDF (charts custom-painted, width-bounded so nothing overflows the page) or as
  an RFC 4180 CSV, and shared via the platform share sheet. Reports are read-only
  and never write to Firestore.
Recommended next work
---------------------
1. Refactor TransactionItem into a serializable Transaction model stored as integer
   cents (not double) with a categoryId reference, updatedAt, and sync status.
   Currently amounts are stored as USD doubles and the display subtitle is
   persisted as-is, which is lossy for editing/analytics.
2. Add per-document updatedAt and conflict resolution. Firestore offline persistence
   and a SyncStatus banner (offline / syncing) are now in place, but concurrent edits
   to the same record on two devices are still last-write-wins.
3. Add encrypted offline storage for Android/iOS/macOS (for example Drift +
   SQLCipher) and keep the encryption key in flutter_secure_storage. Firestore
   offline cache alone is not a complete app-controlled encrypted local database.
4. Design conflict handling and an offline sync queue before treating the local
   database as the primary source of truth. Firestore's on-device queue already
   replays offline writes, but conflicts (same record edited on two devices) are
   last-write-wins.
5. Android boot/package-replaced receivers are configured so pending reminders
   survive reboot and app replacement. A future background scheduler could refresh
   changed reminders while the app remains unopened; this requires Android-specific
   background work and careful Firestore authentication.
6. Expand widget and integration coverage around Firebase sync, notification
   permissions, dialog flows, and offline behavior.
7. Add password reset, resend-email cooldown, account deletion, error telemetry, and
   App Check before production release.
8. Analytics/reports polish: dark-mode chart palette (currently light theme only),
   add chart illustrations to the other PDF statements (only the trend/forecast
   charts are drawn), and persist report period selections. The Trends card's
   adaptive default granularity is verified via unit tests; device smoke tests for
   PDF overflow on real phones are still the user's job.

  Settings and converter pages include this attribution. Cache rates locally before
  production use to avoid unnecessary calls.
