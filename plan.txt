================================================================================
EXPENSE TRACKER — STATISTICS MODULE IMPLEMENTATION PLAN
================================================================================

Goal: Build a self-contained, reusable Statistics module (engine + analytics
service + chart widgets + stat cards) that can be dropped into a Statistics
screen. No redesign of the existing app. Statistics will be reachable from a
new entry in the dashboard side menu (drawer).

This file is a phased plan only — no code is implemented yet. Work will be split
into small one-at-a-time tasks; each task is implemented and verified (analyze +
tests) before the next begins.

--------------------------------------------------------------------------------
1. EXISTING ARCHITECTURE (what we build on)
--------------------------------------------------------------------------------
- State management: `FinanceAppState extends ChangeNotifier`, exposed via the
  `FinanceAppScope` InheritedWidget (lib/state/finance_app_state.dart).
  `main.dart` rebuilds the scope whenever the notifier fires (revision counter).
  => Follow this existing pattern. (User asked: "Riverpod — use whatever state
     management already exists if different". No new provider package needed.)
- Repository: `FinanceRepository` (lib/services/finance_repository.dart).
  Provides load/watch for transactions, planned payments, debts, shopping items,
  budgets, savings goals, notifications.
- Models: lib/models/finance_models.dart
  - TransactionItem{ id, title, subtitle, amount, icon, iconColor,
                     categoryName, note, negative, createdAt }
    - amount is USD internally; negative == expense.
    - `state.transactions` exposes the FULL hydrated in-memory transaction list.
  - BudgetCategory, SavingsGoal, DebtItem, ExpenseCategory also available.
- Currency: utils/currency_settings.dart + utils/currency_formatters.dart
  (formatCurrency, CurrencySettings.toUsd / .fromUsd / .symbol / .code).
  => ALL money shown through formatCurrency; all dates via createdAt.
- Theme: Material 3, ColorScheme.fromSeed(seed 0xFFF59E0B), scaffold bg 0xFFF7F5EF.
  No dark mode yet. Statistics module adds dark/light support.
- Entry point: Dashboard AppBar has a `menu` icon that opens `_AppDrawer`
  (lib/pages/dashboard_page.dart). A "Statistics" item will be added there.

--------------------------------------------------------------------------------
2. NEW DEPENDENCIES (pubspec.yaml)
--------------------------------------------------------------------------------
- fl_chart (^0.69.x)          -> charts (line, bar, pie, scatter).
- intl (^0.19.x / ^0.20.x)    -> date formatting + calendar/weekday labels.
  (Use the version that resolves cleanly with the existing SDK.)
Wrap all fl_chart usage behind our own chart widget wrappers so the library can
be swapped later without touching business logic.

--------------------------------------------------------------------------------
4. DATA / MODELS
--------------------------------------------------------------------------------
DateRange: detected presets
  {today, yesterday, last7, last30, thisMonth, lastMonth, thisYear, custom}
  Fields: start(DateTime), end(DateTime), and a label + a previous-period window
  (same length immediately before `start`) so all "vs previous period" compare.

Compute previous period automatically:
  previous = DateTimeRange(start - (end-start), start).

Core computed models (pure, theme-independent):
  PeriodWindow { range, previousRange }
  SeriesPoint { DateTime x; double y; }
  TrendSeries { List<SeriesPoint> points; double deltaPercent; double current; double previous; }
  GroupedBar { label; double income; double expense; double net; }
  CategoryStat { id, name, icon, color; amount; percent; avg; max; min; count; perDay; monthlyAvg; }
  TopExpense { TransactionItem txn; }
  GaugeResult { double value; double ratio; String label; _HealthLevel }
  ForecastPoint { DateTime x; double value; bool forecast; }

All money kept as double (USD) internally, converted only for display.

--------------------------------------------------------------------------------
5. DATA LAYER
--------------------------------------------------------------------------------
5.1 Repo integration
  analytics_repository.dart reads:
    - transactions        -> FinanceAppScope/FinanceAppState.transactions
    - budgets            -> FinanceAppState.budgets
    - savings goals      -> FinanceAppState.savingsGoals
    - debts              -> FinanceAppState.debts
  No new Firestore reads — reuse the already-synced in-memory state (offline
  proof, single source of truth, no extra loading).

5.2 Analytics service (analytics_service.dart) — pure, NO UI trigger:
    calculateBalance(rows, window)
    calculateCashFlow(rows, window)
    calculateCategorySpending(rows, range)
    calculateMonthlyTrend(rows, range, granularity)
    calculateDebtRatio(debts, income)
    calculateSavingsRate(income, expense)
    calculateTopExpenses(rows, n=5, week=?)
    calculateIncomeExpenseComparison(rows, range, granularity)
    calculateFinancialHealth(rows, range)
    calculateCategoryAnalytics(rows, range)
    calculateIncomeAnalytics(rows, range)
    calculateLongestStreak / daily-balance series / forecasts / heatmap cells.

5.3 Memoization / selectors
  - FinanceAppState already only notifies when the underlying list changes; the
    statistics page wraps its work in an AnalyticsController (ChangeNotifier).
  - The controller holds a per-(raw data identity,dateRange) cache keyed by a
    cheap hash of (transactions.length, lastCreatedAtUs, range.code) so re-builds
    only recompute when the data OR the selected range actually changed.
  - selectors.dart exposes stable lookups so dependent widgets rebuild narrowly.

6. PROVIDERS / CONTROLLER
  analytics_controller.dart: ChangeNotifier
    - exposes current `DateRange` + `CustomRange`.
    - exposes lazily-computed cached StatisticsBundle for the active range.
    - attaches weakly to FinanceAppState; can live in a FiniteStateScope above
      the statistics route (no app-wide provider package needed).
  DateRange picker widget reuses the same presets; changing it calls
  controller.selectRange(...) -> notifyListeners() -> charts rebuild (animated).

--------------------------------------------------------------------------------
6. UI / REUSABLE WIDGETS + CHARTS
--------------------------------------------------------------------------------
Charts (all inside lib/analytics/chart/):
  stat_line_chart  : LineChartArea with baseLine, optional filled area gradient,
                     gridlines, touch tooltip, horizontal drag disable pinch.
  stat_bar_chart   : positive/negative + grouped income/expense/net bars.
  stat_donut_chart : donut + animated rotation + center label that updates on
                     slice tap (selected category / amount / %).
  stat_histogram   : heatmap grid, darker = higher spend; tap day -> list.
  stat_calendar    : monthly grid; each day shows income/expense/balance;
                     tap -> day transactions.
  stat_circular_gauge : arc gauge for ratio cards (DTI, budget, health).

Reusable cards (each: loading/empty/error/data via small Stateful wrapper):
  StatCard, StatSummaryCard, StatSegmentControl, recording as stacked "Stat*Card"
  classes for the 20 requested statistics.

Period buckets:  Daily | Weekly | Monthly | Yearly for trend/aggregation controls.

ALL money shown via formatCurrency; all dates via intl after storing a shared
DateTimeFormatSet; respects a user-selected display currency.

--------------------------------------------------------------------------------
8. THEME  (LIGHT + DARK)
--------------------------------------------------------------------------------
- Introduce a ThemeService/controller storing `themeMode` (light/dark/system).
- MaterialApp exposes @acceptable dark ThemeData (dark scaffold bg, Material 3
  `ColorScheme.fromSeed(seed 0xFF..F59E0B, brightness: dark)`).
- Every chart wrapper takes colors from `Theme.of(context)` + a charts
  `ChartPalette` resolved per brightness so all cards adapt automatically.
- Colors remain argument-injected (no hardcoded palette inside analytics widgets).

--------------------------------------------------------------------------------
9. RESPONSIVE + ACCESSIBILITY
--------------------------------------------------------------------------------
- LayoutBuilder / MediaQuery: charts keep aspect ratio and min tap targets;
  single-column on phone, multi-column grid on >600dp.
- Tooltips use Semantics / ExcludeSemantics; every actionable row is an
  Inline Semantics button; contrast checked for dark/light.
- Large text support: use Theme text styles (no fixed pixel sizes where a card
  can scale); charts have minimum physical size set via media.
- Landscape: wraps into a horizontal grid; cards keep min widths.

--------------------------------------------------------------------------------
10. PERFORMANCE
--------------------------------------------------------------------------------
- All computation cached in controller (section 5).
- Only affected widgets subscribe to their own derived selector.
- Charts: set `isInteractive`, disable pinch, reuse `FlTitlesData`; avoid
  rebuilding the controller on frame callbacks.
- Long heatmap/calendar built in O(n) with precomputed per-day maps.
- No compute on build; compute is idempotent and memoized.

--------------------------------------------------------------------------------
10. ANIMATIONS
--------------------------------------------------------------------------------
- fl_chart built-in `curves`/`duration` for line/bar/circle entrance.
- AnimatedSwitcher on center label of donut; implicit animations on cards.
- TweenAnimationBuilder for balance/cash values when data changes.
- AnimatedOpacity/AnimatedSlide for empty->data transitions.
- All durations ~250-400ms easeOutCubic, matching app feel.

--------------------------------------------------------------------------------
11. ENTRY POINT / NAVIGATION
--------------------------------------------------------------------------------
- Add "Statistics" as an item in the dashboard `_AppDrawer` (dashboard_page).
- It pushes `StatisticsPage` (MaterialPageRoute).
- StatisticsPage is a simple composable Scaffold placing whichever cards the
  user wants, each card accepting a range controller. Cards are reusable and
  could equally be placed on dashboard or elsewhere.

--------------------------------------------------------------------------------
12. TESTING
--------------------------------------------------------------------------------
- unit: analytics_service.dart (aggregations, deltas, %, debt ratio, streaks).
- unit: date_ranges + period math (previous window correctness, leap years).
- widget: chart wrappers & stat cards loading/empty/error states.
- widget: range change updates chart data (fake frame advances).
- Keep isolated; avoid Firebase (no IO in these tests).
